# Data Layout

`CITADEL` uses three data locations inside the repo:

- `data/external_sources.json`: versioned source registry for reproducible downloads
- `data/telemetry/`: local real telemetry snapshots downloaded from the registry
- `data/sample/`: a synthetic deterministic dataset generated locally by `scripts/generate_sample_data.py`

## Real telemetry snapshots

Store real telemetry under `data/telemetry/` through `scripts/prepare_external_data.py`. Large CSVs are ignored by git. The script writes a local manifest under `data/external_manifests/`, and each experiment writes input hashes into `run_manifest.json`.

The DDR4/DDR5 telemetry source is:

```bash
python scripts/prepare_external_data.py --source ddr_data --download
```

It downloads to `data/telemetry/processed/ddr_data/`. This is the path used by the CITADEL CINTAS experiments.

The Apple M2 Pro tiered telemetry source is:

```bash
python scripts/prepare_external_data.py --source apple_data --download
```

It downloads to `data/telemetry/raw/apple_data/`. This dataset supports the paper's platform-diversity and limited-observability discussion. Keep its claims separate from hardware-counter CINTAS area and power claims unless a matching hardware-counter schema is added.

The DDR4/DDR5 snapshot contains:
- 78 CSV files total
- about 1.23 GB on disk
- `DDR4`: `benign`, `DROOP`, `RH`
- `DDR5`: `benign`, `DROOP`, `SPECTRE`
- 13 workloads for each available setup/scenario combination

The loader accepts filenames in the form:
- `DDR4_benign_<workload>.csv`
- `DDR4_DROOP_<workload>.csv`
- `DDR4_RH_<workload>.csv`
- `DDR4_SPECTRE_<workload>.csv`
- `DDR5_benign_<workload>.csv`
- `DDR5_DROOP_<workload>.csv`
- `DDR5_RH_<workload>.csv`
- `DDR5_SPECTRE_<workload>.csv`

If a setup/scenario combination is missing from a particular snapshot, the pipeline skips it instead of failing the whole run.

The CSVs currently contain an autogenerated unnamed first column from the original export. `exact.io` now strips that column automatically so the index does not leak into the feature set.

For CITADEL/TCAD, add new server, embedded, drift, firmware, workload-shift, and aging-proxy snapshots as immutable subfolders or clearly versioned filename prefixes. Do not overwrite a snapshot after it has appeared in a run manifest.

For laptop smoke runs on the external DDR data, fetch only a small workload subset:

```bash
python scripts/prepare_external_data.py \
  --source ddr_data \
  --workloads dft,mm \
  --download

python scripts/run_tcad_ablation.py \
  --data-root data/telemetry/processed/ddr_data \
  --out-root results/citadel_xoctane_smoke \
  --preset smoke
```

## Synthetic sample dataset

The synthetic dataset is only for smoke tests and portability checks. Regenerate it with:

```bash
python scripts/generate_sample_data.py --out-root data/sample --seed 123
```
