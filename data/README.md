# Data Layout

`CITADEL` uses three data locations inside the repo:

- `data/external_sources.json`: versioned source registry for provenance
- `data/telemetry/`: real telemetry snapshots tracked with Git LFS
- `data/sample/`: synthetic deterministic data generated inside the notebook for smoke checks

## Real telemetry snapshots

Store real telemetry under `data/telemetry/`. The notebook locates these folders automatically:

- `data/telemetry/processed/ddr_data/`: DDR4/DDR5 hardware-counter telemetry for CITADEL CINTAS experiments
- `data/telemetry/raw/apple_data/`: Apple M2 Pro tiered telemetry for platform-diversity and limited-observability studies

The Apple dataset supports the paper's platform-diversity and limited-observability discussion. Keep its claims separate from hardware-counter CINTAS area and power claims unless a matching hardware-counter schema is added.

The DDR4/DDR5 snapshot contains:
- 78 CSV files total
- about 1.23 GB on disk
- `DDR4`: `benign`, `DROOP`, `RH`
- `DDR5`: `benign`, `DROOP`, `SPECTRE`
- 13 workloads for each available setup/scenario combination

The loader accepts filenames in the form:
- `DDR4_benign_<workload>.csv`
- `DDR4_DROOP_<workload>.csv`
- `DDR4_RH_<workload>.csv`
- `DDR4_SPECTRE_<workload>.csv`
- `DDR5_benign_<workload>.csv`
- `DDR5_DROOP_<workload>.csv`
- `DDR5_RH_<workload>.csv`
- `DDR5_SPECTRE_<workload>.csv`

If a setup/scenario combination is missing from a particular snapshot, the pipeline skips it instead of failing the whole run.

The CSVs currently contain an autogenerated unnamed first column from the original export. `exact.io` now strips that column automatically so the index does not leak into the feature set.

For CITADEL/TCAD, add new server, embedded, drift, firmware, workload-shift, and aging-proxy snapshots as immutable subfolders or clearly versioned filename prefixes. Do not overwrite a snapshot after it has appeared in a run manifest. Add any new data path to the notebook configuration cell before using it in paper results.

## Synthetic sample dataset

The synthetic dataset is only for smoke tests and portability checks. The notebook regenerates it when `DATA_MODE` is set to `sample`.
